# Contributing

## Making changes

1. Create a focused branch from `main`.
2. Add or update the relevant documentation.
3. Use clear commit messages.
4. Open a pull request explaining what changed and why.
5. Obtain the appropriate review before merging.

## Documentation standards

- Use Markdown for written documentation.
- Give documents clear titles, owners and version information where appropriate.
- Record significant technical decisions as ADRs in `engineering/adr/`.
- Keep diagrams in their source format and export presentation-ready versions to `assets/diagrams/`.
- Update linked documents when a decision changes.

## Security

Do not commit passwords, API keys, access tokens, personal data, customer-confidential information or production datasets.
